# Technical Notes — magic numbers, IBKR quirks, limitations

Last updated: 2026-04-15

Load when editing the notebooks or debugging a data fetch. Not needed to read results.

## Magic numbers & non-obvious code

- **`secs.iloc[1140:]` in barsToCleaning.ipynb** — drops the first 1,140 rows of the 1-second data,
  which had zero volume (pre-market rows from IBKR before an identified data gap). **This number must be
  recalculated if new sec data is prepended to `NewGoodOldGoodOld.csv`.** Filtering by `volume > 0` is
  more robust — but note the tick-based fetch (Section 2 of gettingData) always writes `volume=0`, so
  for newly fetched data rely on the `time` column filter instead.
- **SDV thresholds in preparing.ipynb** — the standard-deviation bins for `open_close_diff_sdv_interval`
  are computed dynamically from the dataset's own mean and standard deviation. They are **not fixed**;
  they shift as data is added.
- **Holiday date list in barsToCleaning.ipynb** — hardcoded list of CME early-close/holiday dates.
  Must be manually updated each year against the CME holiday calendar.
- **`VIX_TICKER = '^VIX'` and `categorize_vix()` in preparing.ipynb (Section 13)** — VIX thresholds
  (`[0, 15, 25, 35, inf]`) are **fixed absolute values**, unlike the dynamically-computed SDV bins.
  `vix_favorable` uses an upper bound of **30**, not 35: trending/panic behaviour starts dominating
  above 30 even though the `'Elevated'` band extends to 35 (a deliberate split — analytical granularity
  vs. trade filter). The MultiIndex column flatten (`vix_raw.columns.get_level_values(0)`) is required
  for yfinance >=0.2.x, which returns multi-level columns even for single-ticker downloads.

## IBKR data subscription notes

- **`whatToShow='TRADES'`** requires an active CME Real-Time (NF2) subscription with live entitlement.
  Error 162 "HMDS query returned no data" for TRADES but not MIDPOINT means the commission-waiver
  condition isn't being met. **Both sections of `gettingData.ipynb` use `whatToShow='MIDPOINT'`** as the
  reliable fallback — prices differ by at most 0.125 ES points (half a tick), negligible here.
- **Section 1 (1-min bars)** uses `reqHistoricalDataAsync` — IBKR retains 1-minute data for years.
- **Section 2 (1-sec bars)** uses `reqHistoricalTicksAsync` — same backend as TWS Time & Sales, and
  reaches further back than the HMDS 1-second bar endpoint (~30 days retention). Fetches raw ticks for
  09:30–09:31 per day and snaps each to the last tick price at or before each target second.
- **`reqHistoricalTicksAsync` datetime format** — use UTC with dash notation: `'YYYYMMDD-HH:MM:SS'`
  (e.g. `'20240311-13:30:00'`). The `'YYYYMMDD HH:MM:SS US/Eastern'` format causes Error 10314 in some
  TWS versions for this endpoint, even though it works for `reqHistoricalDataAsync`. Convert with
  pandas — `tz='US/Eastern'` → `tz_convert('UTC')` → `strftime('%Y%m%d-%H:%M:%S')` — which handles DST.
- **`reqHistoricalTicksAsync` accepts only ONE of startDateTime / endDateTime** — passing both causes
  Error 10314. Use `startDateTime=utc_str, endDateTime=''` to fetch forward from 09:30:00.
- **`numberOfTicks=1000`** is the per-request cap. If exactly 1000 ticks come back for a day, the window
  may have been truncated — paging would be needed (not implemented).

## Known limitations

- Contract location data is auto-generated by `getNadexContracts.ipynb` from Nadex settlement PDFs at
  `https://s3.amazonaws.com/market-data-prod.nadex.com/YYYYMMDD_tradingResults.pdf`. Run it before
  `barsToCleaning.ipynb`. PDFs publish after market close — **same-day contracts still need a manual
  lookup on nadex.com**.
- The 1-second fetch window (09:30–10:00) and contract month live in the **CONFIG cell** at the top of
  `gettingData.ipynb`. Update `CONTRACT_MONTH`, `MINUTES_END_DATE`, `SECS_START_DATE`, `SECS_END_DATE`
  before each run. Contract month as of this writing: `202606` — **update each quarter** (Mar/Jun/Sep/Dec).
- Equal-direction rows (~20%) are excluded from `clean.csv`, preserved in `equal_rows.csv`.

## Prerequisites

- **IBKR TWS or IB Gateway** on `localhost:7496` — **only for `gettingData.ipynb`**. Notebooks 2–4 don't
  connect to IBKR.
- **Internet access** for `preparing.ipynb` Section 13 (VIX via `yfinance`).
